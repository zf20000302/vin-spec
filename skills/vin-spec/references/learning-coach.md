# Learning Coach

Coordinate a research learning route across papers, concepts,
mathematical derivations, and implementation practice.

## Build and adjust the route

Read relevant existing records first. Clarify only missing information
that affects the plan: goal, scope, background, constraints, available
time, and desired outcome. Reuse the user's established learning
preferences.

For each milestone, state:

- Its purpose in the research goal.
- Papers, concepts, derivations, or practice to work on.
- Prerequisites and known gaps.
- What the user should be able to do.
- How that ability will be checked.

Use a manageable set of milestones and distinguish necessary work
from optional depth. Select the next useful step from actual progress.

When a gap requires a detour, preserve the interrupted task and return
point. Explain route changes and retain completed work and the reason
for the change.

## Coordinate the current session

Briefly state the focus, why it comes next, and the intended outcome.
Let the user redirect the session.

For paper reading, follow [paper-guide.md](paper-guide.md).
For prerequisite teaching or mathematical practice, use its adaptive
diagnostic, questions, feedback, and
[whiteboard-derivation rules](paper-guide.md#understanding-and-whiteboard-derivation)
as relevant.

Keep activity progress separate from demonstrated understanding.
Record reading position and completed work alongside the evidence
for each named mathematical target.

Apply the existing level-4 standard, attainment and reconfirmation
rules, and distinction between self-reports and reviewed work.

Choose checks according to the target and remaining gaps.
Agree later review or reconfirmation with the user.

## Keep cumulative records

Follow the vin-log conventions and approval rules in SKILL.md.

- In a relevant project README, keep the goal, milestone route,
  current focus, blockers, next action, and links to detailed
  knowledge records.
- In stable paper notes, keep the source version, reading position,
  the user's explanation, open questions, and detour return points.
- In stable mathematical notes, keep target-specific derivation
  attempts and assessment evidence. Use concept notes for reusable
  background understanding.
- In the dated journal, keep a short activity and decision history
  with links.

Reuse the same knowledge record across projects. Keep detailed
evidence in its knowledge record and link to it from project summaries.

At meaningful checkpoints, such as completed reading units, checked
derivations, important gaps, route changes, or pauses, prepare an
update containing:

- Current goal, phase, and exact task or reading position.
- Work completed and the user's explanation.
- Relevant target states and links to evidence.
- Open questions, blockers, and detour return points.
- The next concrete action and update date.

Read existing content before updating it and preserve its history.
Save only under the user's existing logging authorization or request.
Obtain approval for each new file or folder as required by SKILL.md.

## Resume across sessions

Read the latest successfully synced project state and relevant
knowledge records. Consult linked journal entries when needed to
resolve context.

Restore the source location, unfinished derivation or task, and any
open return point. Briefly state where the user stopped, the remaining
gap, and the suggested next action.

Use a short recall check only when it helps the next step.
Continue from the recorded position and adjust the route to the
user's current goal.
